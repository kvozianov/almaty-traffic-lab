# Abay Scenario Dossier — 6-Minute Demo Script

## 0:00–0:40 — Scenario and evidence boundary

Open the dossier route. State that this is a reviewable decision dossier for one Abay Avenue signal-retiming scenario, not a live control system. Point to the visible claim labels: workflow evidence is `demo`, model findings are `proxy`, and road-geometry provenance does not calibrate the model.

## 0:40–1:30 — Controlled pair

Show the scenario summary and assumptions. Explain that baseline and measure share the same seed, aggregate demand control and input evidence. The only registered difference is the declared signal-delay sensitivity input. This makes the comparison inspectable; it does not prove field impact.

## 1:30–2:20 — KPI evidence

Show the KPI table. Read the serialized baseline, measure and delta values directly from the dossier rather than recomputing them on screen. Highlight that placeholder-sensitive economics and proxy mobility indicators cannot produce an unconditional funding decision.

## 2:20–3:05 — Evidence gate and recommendation

Open the evidence gate. Confirm the permitted decision is to request more evidence. Explain the missing observed counts, travel times, signal plans, bus reliability, sourced costs and acceptance evidence. Do not describe the dossier as procurement-ready.

## 3:05–3:45 — Run passport and reproducibility

Open the run passport. Identify the immutable run ID, scenario ID, source-manifest hash, source fingerprints, command boundary and limitations. Explain that the public server validates the promoted immutable pack before rendering it.

## 3:45–4:30 — Downloads and auditability

Use the download actions for HTML, JSON evidence, KPI CSV, run passport and procurement index. Note that each download is an allowlisted attachment whose path, hash, byte count and run binding are rechecked by the server. Use print/save-as-PDF only as a presentation export of the same dossier.

## 4:30–5:20 — Limitations and next research step

Show the limitations and data-readiness sections. State clearly that the next legitimate step is a separately preregistered observed-data study with calibration/holdout evidence, not an upgrade based on software checks.

## 5:20–6:00 — Technical close

Summarise the chain: scenario configuration → controlled pair → KPI/evidence JSON → immutable release → dossier and hash-verified downloads. Invite a reviewer to use the documented candidate verification command. Any version/tag, license, citation or public-release assertion remains pending the owner decisions and final release gates.
